Personal Assistant · UI/UX 重构

三个方向，选一版

我把项目现状（544 个 Kotlin 文件 / 9 个 feature 模块）的界面代码通读了一遍， 找出真正的问题，再画了三套可直接落地到 Jetpack Compose 的界面方案。
三套方案共用同一个品牌色（静谧蓝 #0B57D0）、同一套可访问性底线 （字号 ≥ 10dp、可点区域 ≥ 44dp、正文对比度 ≥ 4.5:1）， 差别只在布局语言与颜色的使用方式 —— 这样比出来的差异才是真实的。

A

秩序 · Order

语义色收进封闭系统，每屏只留一张主视觉卡，清单项改成卡片， 课表网格加宽并支持横滑、补上当前时刻线。最平衡的一版：数字都看得清，结构也清楚。

三版各自的代价

没有免费的那一版
  • A卡片多了一层，清单页视觉上比现状「重」； 课表横滑意味着看周一要先滑一下；记账报表收进二级页后，看趋势多一步。
  • B分隔变弱，长列表里定位一条靠的是字重不是线； 课表 44dp 列里只塞得下课程名，地点教师要点开才知道；日历默认周视图， 「这个月哪天有空」反而要多点一次。
  • C一屏能看的内容最少； 课表从网格改成时间线，意味着「这周总共有几节课」需要另找入口； 日历不再有月格子，找「某个月哪天有事」会变慢。
  • 共同三版都改变了操作路径： 无论选哪版，筛选、批量、左滑删除这些交互都要跟着重新对一遍，不存在「只换皮不改逻辑」。

如果让我选

供参考，伙伴随意
  • A方案 A 打底 + 方案 C 的课表。 A 的颜色与层级最稳，C 的「今日时间线」解决了 7 列挤 43dp 这个硬伤 —— 网格确实不该在 360dp 屏上硬放。
  • B方案 B 打底 + 方案 A 的记账首屏。 清单和流水确实需要密度，但「今日剩余」这种每天都要看的数字压成一行会让人不安心， 留一张卡更踏实。
三套方案的静态原型都放在 docs/ui-mockups/，用浏览器直接打开即可 （shared/mock.css 是共用的手机外壳层，shared/icons.js 是图标精灵）。
全部界面按 360×800 dp 基准绘制，所有文字使用真实内容而非占位符； 三套方案均通过脚本自检：正文对比度 ≥ 4.5:1、字号 ≥ 10dp、可点区域 ≥ 44dp、无横向溢出。
