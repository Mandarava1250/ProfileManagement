方案 A · 秩序

核心思路：把颜色收进一套封闭的语义系统，把信息层级重排成「一条主轴」。 品牌蓝只负责「交互与强调」，收入 / 支出 / 超支 / 当前时刻各有各的固定色，不再随主题色漂移； 卡片从四档底色收敛到两档，圆角从三档收敛到两档；每个模块只保留一张主视觉卡， 次要信息降级成可点的入口行，列表内容优先于统计图表。

方案 A 相对现状改了什么

  1. 颜色语义封闭。「收入 / 支出 / 转账 / 超支 / 当前时刻」各给一个固定值，永不跟随用户主题色；现状里收入在报表是主题蓝、在流水是绿，支出有两个红（MonthlyReportCard.kt:116 vs TransactionRow.kt:170），「当前时刻」和「超支」共用 error（WeekCalendarView.kt:436）。
  2. 旧色残留清掉。事件分类默认紫 #6750A4（Event.kt:70）、习惯默认樱花粉 #FF69B4（Habit.kt:17）、抽屉清单色 fallback 热粉（ChecklistDrawer.kt:353）统一进蓝系/中性色。
  3. 用户自选色上的前景色一律走 onColorFor() 亮度判断，浅色分类不再配白图标（现状 CategoryManagementDialog.kt:346-353 等 5 处写死白）。
  4. 卡片从四档底色收敛到两档（surface / brand-soft），圆角从 12/16/20 三档收敛到 20（卡）与 12（chip），与 AppRadii 对齐；间距只用 4/8/12/16/20/24。
  5. 记账首屏只留一张主视觉卡（今日剩余），零钱池 / 报表 / 账户合计降级成可点入口；流水不需要滚过 4 张卡才看得到（现状 FinanceScreen.kt:341-380）。
  6. 清单的元信息与标题左缘对齐，子项缩进 22dp 且带竖向引导线（现状父子只差 4dp，ChecklistItemCard.kt:230）；完成率从会滚走的卡片改成固定在顶部的焦点条。
  7. 课表网格可横滑、列宽 60dp，课程卡左侧 3dp 课程色条 + 名称 + 地点两行；补上当前时刻线（现状完全没有，TimetableGrid.kt 全文无 now-indicator）。
  8. 日历月视图 4dp 圆点改 8×3px 色条，可分辨度从「4 个点挤在 40dp 格内」提升；农历角标 9→10px，对比度提到 4.5:1 以上。
  9. 所有可点区域 ≥ 44dp（现状日历「设置时间段」按钮 28dp、日历内习惯打卡 32dp）。
