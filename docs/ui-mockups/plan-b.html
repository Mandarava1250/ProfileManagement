方案 B 相对现状改了什么

  1. 取消卡片壳。清单项从「无底色的行」改成「有底色的行」并不划算 —— 现状反而是统计卡有底、任务行没底（CompletionStatsCard.kt:40 vs ChecklistItem.kt:140），层级倒挂；方案 B 索性统一成「全是行」，用 0.5px 细线分隔。
  2. 统计从卡压成一行。完成率、预算、结余全部变成顶栏下的 30px 一行，节省约 180px 纵向空间，列表可见条目数约为现状的 2 倍。
  3. 记账首屏只剩一行概览 + 流水，零钱池 / 报表 / 账户合计 / 预算全部收进 chip 切换的二级页，解决「想看流水要滚过 4 张卡」（FinanceScreen.kt:341-380）。
  4. 颜色语义照搬方案 A，但容器底色从 2 档砍到 1 档（surface-2），圆角从 20/12 降到 12/8 —— 密度高了以后，大圆角会显得「空」。
  5. 日历默认改成周视图，因为「一周有事」的查看频率远高于「一个月有事」，月视图退到下拉切换。
  6. 课表保持 7 列并排（44dp/列，一屏放得下），代价是课程块只留名字，地点与教师移到点击详情 —— 这是现状 TimetableGrid.kt 那套 43dp 挤 7 列的改良版：至少列宽从 43 提到 44、字号从 12sp 提到 10.5dp 且不再挤爆。
  7. 触控目标仍然 ≥ 44dp：紧凑来自「少用色块、合并统计」，不是把按钮做小。现状日历里的 28dp / 32dp 按钮（DayCalendarView.kt:365、HabitCheckInSheet.kt:180）本方案不允许复现。
方案 B · 紧凑 —— 静态原型（HTML/CSS，无交互逻辑）。
另有 方案 A · 秩序、方案 C · 留白、融合版 D，返回总览对比。
